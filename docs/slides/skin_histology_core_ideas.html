skin_histology_sdxl_collab · Technical Overview

Welcome. This deck presents the core ideas behind our skin histology SDXL inpainting pipeline: how we go from raw tiles to 3D volumes and multi-physics simulation inputs.

🎯 Motivation

Why build synthetic histology variants via SDXL inpainting?

Clinical Data Scarcity
  • High-quality 3D histology volumes are rare, expensive, and time-consuming to acquire
  • Generating synthetic variants from existing 2D slices is a practical path to larger, more diverse datasets
synthetic augmentation
Mask-First Editing
  • Inpaint only inside a user-defined mask region; preserve original tissue everywhere else
  • The mask is the ground-truth anchor — what you edit is what the mask defines
semantic-mask-as-GT
Multi-Physics Bridge
  • Light transport: MCX (GPU Monte Carlo) & PyXOpto (CPU MCML)
  • Biophysical parameter estimation: genetic algorithm on optical properties
  • Thermal simulation: finite-difference Pennes bioheat equation
simulation-ready

key insight Single pipeline, multiple outputs — the same LoRA inpainting engine serves 2D tile editing, 3D coherent volumes, and simulation-ready property maps.

This is fundamentally a data-side project: we are not training a medical classifier; we are generating plausible histological variants from limited source data, then using those variants as input to physics simulation stacks.

⚠️ Critical Caution: Zenodo Slice Subsets

The repo contains derived subsets that are not the full 66-slice Zenodo sequence:

  • data/benchmarks/melanoma_3d/original_hr_prepped_tl/ — a 20-slice subset (2_01_a → 2_20_a) padded to common canvas. High-res but not the full sequential volume.
  • data/benchmarks/melanoma_3d/slices/ — legacy low-res stack. Do not use for new tile inpainting, comparisons, or QC plots.

Correct workflow: Use scripts/3d/build_sequential_slice_stack.py on all 66 raw cropped_slices/*.png in source order — it validates sequence contiguity and rejects non-contiguous globs.

Constraint: No large dataset downloads (MATRICS-A, hundreds of GB) for MVP. Everything works with Histo-Seg + synthetic masks + optionally the ~700 MB Zenodo benchmark.

The dataset landscape is deliberately constrained. We are not trying to match the scale of TCGA or MATRICS-A. The derived-subset warning is important: if someone grabs the prepped 20-slice stack and runs analysis, they may make sequential-volume claims that don't hold for the full 66-slice sequence.

This pipeline has five lanes, read left to right. Data: start with Histo-Seg, build pairs CSV, mine tiles, verify HR sources. Geometry: masks come from Grad-CAM, random brushes, or tissue-aware selection; propagated identically through Z. Synthesis: three-phase LoRA loop then patch inpainting. Physics: stack to NIfTI, optical GA, MCX light transport, Pennes thermal. Validation: Z-coherence, sequential integrity, provenance, diagnostics, comparison. Key principle throughout: the mask is the ground-truth anchor.

📌 HistoSeg-First Strategy

Why start with Histo-Seg instead of Zenodo or MATRICS-A?

Why HistoSeg?
  • Curated skin histology with 12-class semantic masks (epidermis, dermis, BCC, SCC, inflammation, glands, hair follicles…)
  • Masks are manually annotated — not synthetic
  • ~150 image/mask pairs — manageable for MVP iteration
  • Coarse binary labels from filename groups: A → non_cancer B/C/D → cancer — guarantees two balanced classes for Phase 2/3 reward
  • Immediate tile-mining: each full slice (e.g. 5000×5000) yields hundreds of 512² candidates
Pipeline Integration Points

Grad-CAMbuild_roi_masks_gradcam.pyClassifier-saliency masks (when checkpoint available)
Why Not Zenodo?

No semantic masks — only coarse region annotations. The 66-slice stack is for Z-coherence benchmarking, not tissue-aware inpainting training.

Why Not MATRICS-A?

Hundreds of GB, out of scope. Pipeline is mask-agnostic — when better data arrives, nothing else changes.

Semantic masks are the preferred ground truth; random masks serve as the practical MVP fallback.

HistoSeg is the proving ground. The 12-class masks let us evaluate how mask quality affects inpainting output without waiting for a YOLO detector. The coarse binary labels are a simple heuristic that works surprisingly well for reward-guided LoRA training.

Epidermis-Air Orientation

For optical simulation, the epidermis-air normal must point consistently (tile top edge).

  • estimate_epidermis_normal.py — fits boundary from segmentation mask (air=0, epidermis=1)
  • select_orient_tile_for_incidence.py — rotates + crops 512² so normal points to top edge. No padded canvas.

Convention: outward normal points air → epidermis. Rotation aligns to image −y (up).

Extract ROI Patches
Full-res crops around mask bbox. Strict mode: bbox ≤ patch size, zero padding.
Inpaint at Model Res
SDXL LoRA at target_size (512), strength 0.55, 40 steps.
Merge + QC
Feather-stitch patches; QC validates seam diff + CIELAB ΔE*.

key Tile-first avoids full-slice resize. Patches extracted, inpainted, merged at original resolution.

materialisation Build tile index CSV (KB) → materialise once to data/artifacts/tiles/materialized_512/ → all three LoRA phases reuse.

The tile geometry pipeline is deliberately simple and stateless. We do not try to align tiles to anatomical structures at this stage — the orientation step runs later for optical GA. Tile filtering is a rejection pipeline: define clear exclusion criteria and randomise within the pass set.

Why This Matters for Physics Simulation
homogenous phantom
Optical/thermal sims need per-label property maps. A geometry-only mask without class info produces physically unrealistic results.
orientation matters
Epidermis-air normal angle affects Fresnel reflection. Arbitrarily rotated tiles give different MCX reflectance.
cylindrical artifact
Real features change shape across slices. Identical (x,y) mask on every slice creates an artificial cylinder.

insight The pipeline is mask-agnostic — better masks directly yield better results. Every stage works with any binary mask; no refactoring needed.

This is the most important slide to convey honestly. Geometry-only masks are a pragmatic starting point. For downstream multi-physics simulation, class-aware masks are essential — and the pipeline is designed to accommodate them with no refactoring.

Murilo port GA loop + forward-modelling ported from Murilo's skin-optics framework. Key differences: (1) integration with 3D label volumes, (2) dual forward-mode (surrogate + MCML), (3) direct L*a*b* targets with ITA° conversion.
bridge build_histoseg_label_volume.py → label_to_optical_priors.py → run_optical_ga_from_labels.py → .npy / .json / .npz
Emphasise the two forward modes — surrogate for rapid prototyping, MCML-based for publication-grade fits. The GA is not a black box: each genome can be visualised as reflectance curve + skin colour swatch. The Murilo port saves ~80% re-implementation time.

Light transport engine comparison — GPU Monte Carlo vs CPU MCML.

Property MCX (Monte Carlo eXtreme) PyXOpto (xopto)
Engine GPU-accelerated (CUDA C++) CPU (Python + C extensions)
Input format Binary voxel volume + JSON config Python API, layered geometry
Speed ~10³–10⁴× faster at scale Adequate for single 1D fits
Output Fluence / absorption volume (.nii/.npy) Reflectance / transmittance curves
Pipeline role mcx_build_volume.py → mcx_batch_runner.py mc_wrapper.py in GA forward model

Strengths High-res 3D volumes, batch studies, GPU scaling Zero GPU dep, easy debugging, pip-installable
Limitations Binary volume conversion step, CUDA-only Slower for voxelised 3D, single-threaded
Why MCX Is Strategic for Future 3D
scalable batch Sweep hundreds of optical-property realisations in minutes on a single GPU. Enables UQ and sensitivity analysis.
native 3D voxels Operates directly on the same .npy label volumes we already produce. No geometry abstraction gap.
optical→thermal Exports per-voxel absorbed energy density (W/m³) — direct source term for Pennes solver. No resampling.
head-to-head batch_compare runs MCX + PyXOpto with shared bounds and identical tissue models for cross-validation.
MCX is not a drop-in replacement for PyXOpto — it requires a volume build step. The batch-compare script is the key tool for trust calibration between the two engines. Frame MCX as an investment: once the volume pipeline is solid, every future study gets GPU-speed light transport for free.

Pipeline & Configuration
  1. NIfTI volume → label volume (.npy)
  2. thermal_build_model.py → property arrays (ρ, c, k, wb, qmet)
  3. thermal_solve.py → explicit FD Pennes solver
  4. thermal_visualise.py → temperature PNG + summary JSON

Config: initial 37 °C · fixed / convective BC · source modes: none spherical optical (future)

Key Coupling Insight

The optical absorption field Q(r) is the only channel through which tissue microstructure enters the thermal model:

  1. Inpainting quality directly affects the thermal source term.
  2. The same label-to-property mapping used for optical priors is reused for thermal — no separate segmentation needed.
  3. Sensitivity of the thermal field to inpainting artefacts can be quantified via perturbed-Q runs.

implemented All three thermal scripts exist. Smoke tests run without GPU.

The optical absorption field Q(r) from MCX is a 3D array with the same voxel grid as the NIfTI volume — no resampling. The coupling insight is that the same label-to-property mapping serves both optical and thermal models. Future: couple thermal back to optical via temperature-dependent chromophore spectra.

Phase A is done. Phase B is the current focus — the tile-first B.1 sub-flow is preferred because it preserves full-resolution tissue architecture. Phase C bridges to physics. Phase D is future work. The roadmap is deliberately incremental: each phase adds capability without breaking the mask-agnostic pipeline design.

Open Research Questions
  1. Semantic mask encoding. How to feed tissue-class info into inpainting? Concatenated channels? Conditioned cross-attention? Separate LoRA per class?
  2. Minimal Z-slice count. Is 10 slices enough to detect coherence degradation? 20? Does the metric saturate?
  3. Optical prior strategy. Per-label region (coarse) vs per-voxel (fine)? Coarse matches MCX input; fine may overfit.
  4. Validation against real histology. Compare inpainted tissue against H&E stain vectors (Macenko norm)? Does non-real stain colour matter for simulation?
  5. Cylindrical validity vs Z-spacing. For >5 μm between slices, does rigid cylinder assumption break down?
  6. Classifier reward generalisation. Does Phase 2/3 reward from Histo-Seg classifier hold for held-out tissue types?
Guiding Principles
  • mask-agnostic
    Editing workflow does not depend on mask source. Better masks directly yield better results.
  • semantic-mask-as-GT
    Long-term goal is class-aware masks, but pipeline works with binary masks today.
  • provenanced intermediates
    Every step logs inputs, parameters, outputs in run manifest. Enables retrospective QC.
